# 运行日志隐私与容量

API 与长期调度 Worker 只记录固定字段的 JSONL 诊断，不格式化原始异常及其 traceback，不记录 URL、查询词、动态包 ID、IP、认证头、Cookie、请求/响应正文、凭据、上游响应或本机路径。允许字段为 UTC 时间、query/worker 角色、固定事件/路由类别/阶段/命令/错误类别，以及有界的状态码、时长、请求数、退出码和服务生成的请求 ID。未知字段丢弃，未知枚举降为固定值；客户端提交的 X-Request-ID 不作日志身份。

日志是可丢弃的运行诊断，不是采集证据、推荐事实、审计账本或用户行为统计。Worker 显式查询和操作的 stdout 结果仍按原命令返回，可能包含调用者请求的元数据/本机操作回执；它不是诊断日志，不应将其永久追加为访问日志。普通一次性 CLI 不额外输出逐行运行事件，失败保留单个安全 JSON 错误；schedule-run 的持续事件经过固定字段过滤。

## 默认与参数

不指定 --log-directory 时，API 和 schedule-run 的诊断写 stderr，控制台容器/服务的保留预算由其运行环境负责。交付中的 compose 示例配置 local 日志驱动、每文件 1m/最多4份；这是未运行的模板，不表示 Docker 已在本机验收。systemd 示例为 API/Worker 分配独立的 LogsDirectory 和0700权限，传入 --log-directory，不给只读公开快照增加写权限。所有模板均未安装、启用或部署。

可选应用文件日志参数：

| 参数 | 默认 | 允许范围 |
| --- | --- | --- |
| --log-directory | 无，使用控制台 | 与 code/catalog/runtime 不相交的独立目录 |
| --log-max-bytes | 1048576 | 4096–16777216，单文件字节 |
| --log-backups | 3 | 1–20，另有一个当前文件 |
| --log-max-age-seconds | 604800 | 3600–31536000 |

默认每角色最多4份、合计不超过4MiB的日志内容，另有小型所有权标记与锁文件；不把文件系统块开销或外部控制台当作该内容预算。写入不切断JSON记录，单条固定字段记录小于最小文件预算，不积攒内存队列。预算降低后若已有单文件超出新上限，启动拒绝并保留原文件，应审阅后选用新日志目录；不会静默截断既有内容。

## 轮换与保护范围

大小轮换在写入前执行；启动和后续事件到达时检查年龄，按每文件最早记录时间整文件到期，可能一并丢弃其中较新的诊断。持续追加不会刷新最老记录的保留期限，时钟倒退会另起文件。不启动后台删除线程，完全闲置/停机期间不承诺到秒自动删除，到下一次启动/事件执行检查。

目录按 query/worker 角色加进程独占锁，线程内串行写入。只操作本角色 query.jsonl 或 worker.jsonl，以及 .1–.20 范围内的已归属轮换文件；不删除外部日志、未知文件或其他角色文件。已有同名文件却无匹配所有权标记、日志头无法识别或末行不完整、symlink/junction/reparse/hardlink、与保护路径相交时拒绝接管。目录应由运行账户独占；这不是对同账户恶意并发改写的隔离沙箱。

运行中遇到日志写入/轮换失败，停止继续向该文件集写入，向安全 stderr 报一次 log_io_error，后续事件也只写固定字段，不让日志故障使HTTP查询失败或积攒无界内存。文件预算不限制 stderr 宿主的总空间；journald等宿主仍须按自身策略保留。本模块从不清理state、观察、first_seen、证据、任务或快照。

## HTTP 与网关

API 关闭 Uvicorn 原始 access log，替换 Uvicorn/asyncio/服务日志处理器，不调用消息或异常参数的格式化。HTTP 记录覆盖正常/限流/错误/预检，保留与响应一致的生成请求 ID。嵌入 create_app 的调用者可通过 event_log 接入相同中间件；原始 uvicorn 日志需由宿主关闭或使用 server_logging 上下文。

nginx示例关闭原始访问日志和请求错误日志，避免外层把原始query重新写盘。代价是示例不保留网关请求失败文本；需要额外网关诊断时，应单独设计脱敏与保留规则。已有宿主其他层级/代理/CDN的日志不受Python模块控制。模板须在实际目标环境中验证后启用。

软件保持0.1.0；state/query/batch首版格式1、规范Schema v2保持。新增运行日志标记不提供开发中间格式迁移。
