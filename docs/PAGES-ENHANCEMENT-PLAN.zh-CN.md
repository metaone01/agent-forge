# GitHub Pages 体验与提交入口增强计划

日期：2026-10-03（Asia/Shanghai）
状态：本地实现与验收完成；main 控制分支集成及线上验收待授权。

本文记录本轮 Pages 功能计划及用户已确认的取舍。2026-10-03 已获准开始实施，并可使用 subagent 并行工作；仍不擅自安装依赖、创建真实 Issue/PR、提交、推送或发布。

## 1. 已确认决策

1. 文档由实现方按适合阅读和查阅的方式组织：项目 README、Schema 总览、四份 Schema 字段参考均提供站内富文本页面，区分项目介绍与契约参考，不把所有内容堆在同一页。
2. 用户标签同时包括 `customFacets` 和 `keywords`。显示顺序为受控 `facets`、用户自定义 `customFacets`、自由关键词 `keywords`；后两者属于用户标签，但保留字段语义区分，不互相转换。
3. 上传采用“站内可视化填写 → 自动生成 Schema v2 JSON → GitHub 预填 Issue → 用户最终确认提交”。当前没有后端，本期不增加后台代提交、OAuth 服务或浏览器写权限 token。
4. 保留独立 Agent JSON 入口，允许直接提供完整 JSON；人类入口不要求用户手写 JSON。
5. `Submission Notes` 为可选项，缺失或为空均不阻止提交和自动化处理。
6. 包标题优先使用 `displayName`，缺失时使用 `name`；不展示 canonical `id` 副标题，不改变包身份、索引键或路由语义。
7. 全站支持简体中文与 English，以及亮色、暗色、跟随系统三种主题模式。

## 2. 范围与边界

### 本期覆盖

- 目录、包详情、Dashboard、Agent Dashboard 的共享导航、语言与主题。
- 项目及 Schema 文档阅读页面。
- 名称/ID 展示和三类胶囊标签。
- 可视化上传页、Agent JSON 入口、Issue 模板及相应解析契约。
- 必要的数据投影与 Pages 构建装配调整、回归测试和浏览器验收。

### 本期不做

- 后端 API、数据库、后台直接创建 Issue、OAuth 登录服务。
- 新增 `tags` 字段或升级 Schema 版本；使用现有 `facets`、`customFacets`、`keywords`。
- 安全认证、上游源码审查、下载或执行安装命令、代理二进制文件。
- 自动翻译包名、上游描述或用户填写的数据。
- 未经许可的环境变更、真实测试 Issue/PR、Git 提交、推送或 Pages 发布。

元数据校验仅验证记录格式和已定义的语义约束，不代表来源、兼容性、checksum、signature、facet 或安装候选已获得安全核验。

## 3. 实施前检查

- 保留现有未提交改动；明确本轮增量，避免覆盖 README、Pages 和 Dashboard 的已有工作。
- 核对最新控制分支、Issue 自动化和发布流程。历史约定是 `main` 管理站点与控制流程、`packages` 保存 canonical 包数据，实施时必须重新验证，不能把旧的本地分支引用当作线上现状。
- 确认 Issue 自动化写入路径、PR 基础分支和校验门槛；发现与实际分支职责不一致时先纠正方案。
- 核对投影是否保留 canonical ID、`name`、`facets`、`customFacets`、`keywords`，避免卡片为展示标签逐条请求包详情。
- 新页面引入后统一站点根路径解析，兼容项目子路径、目录页、Dashboard 嵌套路径与本地预览。源索引路径继续按 `/data/` 相对路径契约解析。
- 核对可用测试与浏览器工具。如需额外 Markdown、高亮、JSON Schema 或测试依赖，先说明名称、用途与维护成本，获得批准后使用；不新增重型前端框架。

## 4. 实施阶段

### 阶段 A：共享语言与主题

#### i18n

- 建立共用中英翻译字典，覆盖静态 HTML 和动态渲染文案。
- 覆盖导航、搜索、筛选、排序、分页、空状态、错误状态、表单提示、图表说明、页面标题及无障碍标签。
- 默认中文（zh-CN），不随浏览器语言自动切换；语言控件显示国旗与对应语言名称，用户显式选择 English 后持久保存。不支持的语言回退中文。
- 日期、数字按当前语言格式化；JSON 字段名、枚举值、包 ID 与 Issue 机器解析标记保持稳定。
- 切换语言不清空搜索、筛选、页码或上传草稿，不重复请求全部索引；存储不可用时仍可正常操作。
- 文档切换语言时尽量保留对应章节；无对应内容时明确回退，不显示空白页。

#### 主题

- 提供亮色、暗色、跟随系统三种模式；控件只显示太阳/月亮/显示器图标，名称用于提示与无障碍标签。默认跟随系统，保存用户显式选择。
- 跟随系统模式实时响应系统主题变化；显式亮/暗模式不被系统变化覆盖。
- 初始绘制前应用主题，减少闪烁；统一 CSS 变量及必要的硬编码颜色。
- 覆盖页面、卡片、表单、胶囊、图表、代码高亮、悬停和焦点状态；确保文字与控件可辨认。

### 阶段 B：富文本文档

#### 信息架构

建议站内文档入口按以下层级组织；最终 URL 可随现有构建方式微调：

- 文档首页：项目介绍、导航与常用入口，对应项目中英文 README。
- Schema 总览：契约关系、两层地址模型、使用边界。
- 字段参考：Package、Source、Index、Advisory 独立页面。
- 各页提供对应语言、目录、标题锚点、原始 Markdown 与机器可读 Schema 入口。

#### 渲染与构建

- 仓库现有 Markdown 是内容源，不维护一套重复正文；明确项目 README 与站点说明 README 的职责，避免取错来源。
- 在 Pages 装配时生成静态 HTML，兼容 GitHub Pages 项目子路径和本地预览，不依赖访问时的外部 CDN。
- 渲染标题、表格、列表、引用、链接和代码块；JSON、TypeScript 及文档实际用到的语言提供语法高亮。
- “彩色渲染”以语法高亮、引用和提示的语义样式为主，不任意给普通正文染色。
- 代码块提供复制，长表格和代码块在窄屏横向滚动。
- 重写 Markdown 相对链接，保持中英文文档互链和锚点有效；正文不执行嵌入脚本，链接与 HTML 按安全边界处理。
- 纳入本地预览、Pages 打包和构建检查，确保生产部署确实携带文档，而不仅本地可见。

### 阶段 C：包标题与胶囊标签

#### 名称与身份

- 标题恢复为 `displayName` → `name`，canonical `id` 仅保留在详情的技术信息中。
- 索引携带最新版本的 `displayName`，保证列表、详情和最近更新展示规则一致；显示名不参与身份和路由。
- 同步目录卡片、详情及 Dashboard 中的包条目；缺失字段明确回退，不把内部组合键误当 canonical ID。
- 不修改路由、索引键、身份、去重或版本选择逻辑；长名称、Unicode 与长 ID 在窄屏可读。

#### 三类胶囊

| 顺序 | 数据来源 | 展示语义 |
| --- | --- | --- |
| 1 | `facets` | 受控 facet，保留 `分组: 值` |
| 2 | `customFacets` | 用户自定义 tag，保留 `分组: 值` |
| 3 | `keywords` | 用户自由关键词 tag，显示关键词 |

- 受控 facet 与用户标签以颜色区分，后两类用样式或文字辅助区分；不能只靠颜色传达类别。
- 辅助说明沿用 Schema 的未核验边界，受控词汇不等于安全认证。
- 空字段、空数组和空分组不生成胶囊；整体无标签时不保留空容器、组数或占位。
- 不跨字段合并同名标签；相同文本也可能有不同语义。
- 卡片使用稳定上限和剩余数量提示，详情完整展示；上限在实际窄屏验证中确定。
- 保留现有搜索能力；这一轮不额外增加未经要求的标签筛选交互。

### 阶段 D：可视化上传与 Agent JSON 入口

#### 人类填写页面

- 页面提供明确的人类表单入口与 Agent JSON 入口，默认可视化表单。
- 必填基础信息对应现有 Schema：包名、ID、版本、类型、描述、license、targets。
- Agent 目标、发行候选、链接、facet、custom tag、keywords 支持可视化增删。
- 对五种包类型提供必要的结构化字段；非 Bundle 的发行候选以及各类型约束按真实 Schema 控制。
- Bundle 成员、General 类型详情等按选择展开；切换类型时不静默丢弃草稿或输出互相冲突的数据。
- 高级字段按需展开，避免把完整 Schema 一次性堆成巨型表单；Schema 不支持的自由格式不伪装成合法字段。
- `schemaVersion` 等固定值自动生成；时间戳等只在语义明确时生成，不虚构上游发布时间、版本、兼容性或发行来源。
- Submission Notes 明确标注可选，不属于 package JSON 本体。
- 提供自动生成的 JSON 预览、复制和下载；用户无需编写 JSON。
- 支持字段级错误、提交前汇总、错误定位和重复条目检查；符合条件后才能生成可提交内容。
- 完整 Schema 校验与跨文件 CI 校验分工清楚，不把前端局部检查宣称为最终校验。

#### GitHub 确认提交

- 统一生成 Issue 标题、稳定的 JSON 区段标记及 JSON 代码块，Notes 有值时再附加可选区段。
- 使用 GitHub 预填 Issue 或现有 Issue Form 的能力，由用户登录并最终确认创建；不在浏览器保存写权限 token。
- 实施时验证具体模板、字段预填与标签处理方式，确保不跳回要求用户手写 JSON 的流程。
- 测试 URL 编码、Unicode、换行、特殊字符和大 JSON，不以未经验证的固定长度假设承诺支持。
- 超出实际可用传递范围时明确提示并提供复制/下载回退；回退入口须仍能提交完整数据，不静默截断。
- GitHub 取消、登录失败或页面返回时不丢失当前填写内容。

#### Agent JSON 入口

- 保留独立 JSON Issue Form，并提供站内粘贴/导入 JSON、校验、复制和下载入口。
- 发布机器可读 Schema 入口、最小完整示例和稳定 Issue 契约，Agent 可通过其已有授权的 GitHub 工具直接提交数据 JSON，无需操作人类表单。
- 使用相同校验与提交序列化逻辑；JSON 导入时保留合法高级字段及 `_meta` 等扩展，不由表单重建而丢失。
- 如果允许把 JSON 切换为可视化表单，必须保证未支持字段保留；无法无损转换时明确限制，不静默删字段。
- 人类界面翻译不改变 JSON 字段、枚举、解析标记或标签契约。

#### Issue 与 PR 自动化

- `Submission Notes` 在 Issue 模板中设为可选，解析器支持缺失、空值及模板空值占位。
- 人类与 Agent 入口汇入同一 JSON 解析和处理链，拒绝无效 JSON，给予明确错误反馈。
- 核对 PR 目标、写入路径和现有包身份规则，保留必要的 Schema、语义与跨文件校验。
- 在正确的控制分支调整相关流程，不把控制工作流复制到数据分支。
- 真实端到端 Issue/PR 测试需要另行批准；批准前使用 fixtures 和离线解析测试。

### 阶段 E：完整验收

| 范围 | 主要验收用例 |
| --- | --- |
| 文档 | 中英页面、目录锚点、语法高亮、表格与代码窄屏、复制、相对链接、构建产物 |
| i18n | 静态与动态文案、无障碍属性、日期数字、状态保留、刷新与存储不可用 |
| 主题 | 三种模式、系统切换、显式选择优先、首屏闪烁、图表和代码对比度 |
| 标题 | name/ID、canonical ID 与内部键区分、Unicode、长名称、名称复制与 ID 复制边界 |
| 胶囊 | 三类顺序、分组语义、无标签、部分标签、重复文本、过多标签、窄屏 |
| 表单 | 五种类型、必填/可选、目标和发行条目、条件字段、重复条目、无 Notes、错误定位 |
| JSON | JSON 导入与无损保留、扩展字段、非法 JSON、编码与长度回退 |
| Issue | 两种入口、稳定解析标记、Notes 缺失、正确目标分支；线上测试需授权 |
| 回归 | 搜索、筛选、排序、分页、详情、版本选择、Dashboard、数据路径与投影 |

- 执行现有单元测试、完整元数据校验、投影生成和 Pages 文档构建检查。
- 执行 JavaScript 语法检查，以及新增测试和适用的 lint/build 检查。
- 使用本地生成的 Pages 站点做桌面与窄屏浏览器验证，不能仅以类型或语法检查代替 UI 验收。
- 最终改动后重跑相关回归；工具或权限不足时明确记录未验证项，不声称验收完成。

## 5. 文件与交付组织

预计涉及以下目录，具体新增模块以最小可维护实现为准：

- `site/`：共享语言、主题、目录展示、文档入口、上传页及 Agent 入口。
- `docs/schema/` 和项目 README：文档内容源，必要时只修正文档链接或说明。
- `tools/`：必要的静态文档构建与投影字段调整。
- `.github/ISSUE_TEMPLATE/`：可视化入口指引、Agent JSON 模板和可选 Notes。
- 控制分支 `.github/workflows/`：Pages 文档装配与提交解析的必要调整。
- `tests/`：投影、文档产物、Issue 解析与提交序列化回归；按可用工具补 UI 测试。

建议按“语言与主题 / 文档 / 包展示 / 上传与自动化 / 验收补充”组织逻辑独立的交付单元。批准计划不等于批准 Git 提交、推送、发布或新增依赖，这些操作分别确认。

## 6. 完成标准

- 六项原始需求均有可运行实现及相应验证证据。
- 人类不必手写 JSON，Agent 不必使用人类表单，双方生成同一种合法记录。
- Notes 可省略；没有标签时不显示空区域；名称与 ID 的展示职责明确。
- 文档、双语言、三种主题在所有本期页面中一致，构建产物能用于实际 Pages 部署。
- 保持 Schema v2 和元数据整合边界，不增加后端或浏览器写权限凭据。
- 交付说明列出改动、已执行验证、未验证项和需要授权的后续操作。
